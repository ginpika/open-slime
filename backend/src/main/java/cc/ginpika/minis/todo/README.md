# 个人待办与投入

`todo` 拥有人的事项、实际投入、每日回顾和历史查询。它不复用 Agent 的 `task` / `agent_todo` / 计划工具，不把模型运行时间推断成人的投入。HTTP 适配位于 `web/controller/PersonalTodoController`；领域与存储不依赖 Web 登录对象，控制器从已认证身份传入 owner。

## 持久化与边界

- `todo/schema.sql` 在 Spring 的 schema 初始化链路中执行，幂等新增五张 `personal_*` 表，不迁移或改写旧 Agent 待办。
- 项目只引用已有 `project.id`。`project_name` 是标签丢失时的显示快照；没有项目级联删除，项目停用不结束个人事项。
- 所有查询和变更按 owner 隔离。输入中没有 owner 字段。
- 变更事务第一条 SQL 写入 owner 锁行，先获得 SQLite 写锁再读取状态，避免 deferred transaction 的读后升级竞争。活动计时还有按 owner 的唯一部分索引兜底。
- 事项与投入修正使用版本校验；开始计时携带预期活动计时 ID，防止旧页面切换其他页面刚开始的计时。旧计时的暂停请求只影响其自己的记录。
- 计划日期与实际投入分离；计时可以在未安排日期的事项详情中开始。开始/暂停不会静默移动计划日期。完成、放下会结算当前计时；重新打开保留历史事件。
- 统计以 UTC 毫秒存储的半开时间区间为依据，按请求 IANA 时区切分日/月边界，兼容跨午夜和夏令时。后台不设置计时最大时长；页面超过 8 小时提示核对，暂停后可修正。
- 计时恢复来自数据库。未结束的记录按当前服务端时间显示，不依赖浏览器是否仍打开。补记不可未来、不可重叠；修正与删除影响统计，并保留修正事件。
- 月度完成数是当前已完成的不同事项数，按当前完成时间归月；重新打开后从已完成数移除。旧完成事件仍可查看，不累积奖励计数。首次完成足迹来源于首次完成事件。
- 日记独立于项目。按项目筛选时，不把全局每日文字归入某个项目；全局回望可阅读和编辑旧日记。

## API

| 路径 | 用途 |
| --- | --- |
| `GET /api/todos/overview?zone=...&projectId=...` | 当前未结束事项、今日结束事项、今日投入、全局活动计时、标签、今日日记 |
| `GET /api/todos/review?month=YYYY-MM&zone=...&projectId=...` | 月度结束事项、实际投入汇总、足迹、日记 |
| `GET /api/todos/projects` | 每个可见项目及未分类的累计事项数、状态数、实际投入；包含空项目与删除后的历史标签 |
| `GET /api/todos/day?day=YYYY-MM-DD&zone=...&projectId=...` | 指定日的真实小时边界、相交投入及关联事项（含当日结束但无计时的事项），day 留空为今天 |
| `GET /api/todos/{id}` | 事项完整资料、投入与事件历程 |
| `POST /api/todos`、`PUT /api/todos/{id}` | 创建、替换资料（更新须携带 version） |
| `POST /api/todos/{id}/state` | complete / drop / reopen，须携带 version |
| `POST /api/todos/{id}/start` | 开始或切换计时，须携带 expectedActiveId（无活动时为 null） |
| `POST /api/focus-sessions/{id}/stop` | 暂停指定计时，可重试 |
| `POST /api/focus-sessions` | 补记实际开始、结束时间 |
| `PUT /api/focus-sessions/{id}`、`DELETE ...?version=...` | 修正或删除已停止记录 |
| `PUT /api/day-notes/{day}?zone=...` | 保存每日回顾，携带 version；不存在时为 -1 |

`projectId` 留空表示全部，`unassigned` 表示未分类。overview 只读取未结束事项与今日结束事项，历史按月查询；不会把全部历史投入下载到前端。

页面 `/todos` 沿用 AppShell、PageSlot、PageKit、Button、FloatWindow 和 AppIcon。当前版本由人明确操作，没有自动 AI 排期、自动记工时或自动写回记忆的副作用。

前端将当前事项总览、项目汇总与资料、月度回顾、指定日时间图独立加载。总览仅含未结束及当日结束事项，项目筛选在这份有界数据上即时完成，仅作用于「今天／全部待办」。时间分配与回望按日期 / 月份查询全局数据，不继承隐藏的待办筛选。各查询在当前页面保留最多 12 份缓存，变更操作、手动刷新及 30 秒轮询使缓存失效；切换日期 / 月份只请求对应的未缓存历史，不清空页面或重建表单。计时更新局限于精力面板和时间图。

项目页将 `/api/projects` 的项目资料与 `/api/todos/projects` 的累计汇总按项目身份合并。总览支持搜索、状态与分类筛选，详情展示目标说明、状态分类、投入与成果摘要和资料编辑；不重复待办清单或完整月度回顾。「查看待办」跳到对应项目筛选的「全部待办」。未关联事项另设入口，已删除项目的历史摘要继续保留。新建 / 编辑复用 `POST /api/projects`、`PUT /api/projects/{id}`，不建立另一套项目数据；事项编辑框内新建项目时保留尚未保存的事项资料，并选中新项目。

时间分配以任务为行，上方为 00:00–24:00 连续时间轴，不另设「全部投入」汇总行。每次投入各占一条精确定位的长条，按开始时间全局编号，同一任务的多段投入不合并。包含完成时间点、当前时间线、2× / 4× 放大与固定任务列。点击长条可查看和修正投入。跨午夜时裁切到所选日期；完成但未计时的事项只显示完成点，不推断投入时长。夏令时日按 23 / 25 小时的真实时间间距定位。空白仅表示未记录，不推断休息。
