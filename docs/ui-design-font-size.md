# UI 字体大小与可读性规范

## 1. 目的与适用范围

本规范用于统一 Web 应用的字体大小、文本层级及可读性要求，确保界面在不同设备、屏幕尺寸和使用场景下保持良好的阅读体验与视觉一致性。

本规范适用于页面标题、正文、表单、按钮、聊天消息、工具栏、状态提示、时间戳、调试日志及其他 UI 文本。

除非具体产品规范另有规定，所有字号均指 CSS `font-size` 使用的逻辑像素（`px`），不代表显示设备的物理像素。

## 2. 字体大小规范

### 2.1 标准字号体系

| 文本层级             | 标准字号  | 典型使用场景                             |
| -------------------- | --------- | ---------------------------------------- |
| 页面标题             | 24–32px   | 页面主标题、独立页面名称                 |
| 区块标题             | 18–22px   | 内容分区标题、主要面板标题               |
| 正文                 | 14–16px   | 段落、说明文本、一般内容                 |
| 核心阅读正文         | 16px      | 聊天消息、Agent 回复、主要阅读内容       |
| 次要文本             | 12–13px   | 时间戳、辅助说明、次要元数据             |
| 标签及紧凑型辅助文本 | 12px 起   | 状态标签、紧凑型表格辅助信息             |
| 极小文本             | 小于 12px | 仅限确有必要的特殊场景，须经过可读性评估 |

16px 是阅读级的舒适区间

以上为项目设计建议值，不是适用于所有产品的普遍强制标准。

### 2.2 最小字号要求

项目应遵循以下默认约束：

1. **常规正文：** 桌面端字号原则上不得小于 14px；移动端正文原则上不得小于 16px。
2. **核心阅读内容：** 默认使用 16px，包括聊天消息、Agent 回复及其他需要连续阅读的主要内容。
3. **次要信息：** 时间戳、状态说明及其他辅助元数据可使用 12–13px，但不得因缩小字号而影响信息识别和操作判断。
4. **小于 12px 的文本：** 不得作为常规 UI 文本的默认字号。确有必要时，必须评估其可读性、对比度、显示效果及无障碍影响。
5. **交互相关文本：** 按钮、输入框、菜单项及其他交互元素中的文本应优先使用 14–16px，避免因字号过小而增加识别和操作成本。

上述要求属于项目内部设计约束。对于特殊数据密集型界面，可在充分评估后作出明确、受控的例外，但不得降低适用的无障碍合规要求。

## 3. 行高规范

行高应与字号、字体特征和文本用途相匹配，避免正文过度紧凑或标题占用过多垂直空间。

| 字号    | 建议行高 | 典型用途           |
| ------- | -------- | ------------------ |
| 12px    | 16–18px  | 时间戳、辅助信息   |
| 14px    | 20–22px  | 次要正文、表单说明 |
| 16px    | 24–26px  | 正文、聊天消息     |
| 18px    | 26–28px  | 区块标题           |
| 20–24px | 28–34px  | 页面及面板标题     |
| 28–32px | 36–40px  | 大型页面标题       |

表格中的行高为建议范围，不是硬性限制。最终值应结合字体度量、中文字符显示效果、段落密度及响应式布局确定。

对于多行正文，应避免使用过小的固定高度或裁剪规则导致文字被截断。

## 4. 字体对比度与可读性

### 4.1 文本对比度

项目应以 WCAG 2.2 AA 作为默认无障碍设计目标。

- 普通文本的前景色与背景色对比度应至少达到 **4.5:1**。
- 大号文本的对比度应至少达到 **3:1**。按照 WCAG 定义，大号文本通常指至少 18pt 的常规字重文本，或至少 14pt 的粗体文本；换算为 CSS 单位时，分别约为 24px 和 18.67px。
- 对比度应根据实际前景色与背景色计算，不得仅凭主观视觉判断。
- 不能仅依靠颜色差异传递错误、警告、成功等重要状态；必要时应同时使用文本、图标或其他可识别标记。

对于透明度、渐变、图片背景等复杂场景，应检查文本实际呈现区域的对比度。

### 4.2 字体与字重

- 优先使用具有良好屏幕显示效果的字体。
- 中文文本应检查常用字符的显示完整性、字面大小及不同字重下的可读性。
- 不得单纯通过使用过细字重或降低透明度来弱化次要文本，以致影响阅读。
- 应确保字体加载失败时存在合理的备用字体栈。

## 5. 响应式与无障碍要求

1. 界面应适配桌面端、平板及移动端，避免因视口变窄而不合理地缩小正文字号。
2. 页面应支持文本放大至 200% 时继续访问主要内容和功能，不得因放大而发生不可接受的内容丢失或功能失效。
3. 对于 WCAG 1.4.12 文本间距要求，界面应能容纳以下用户自定义间距，而不发生内容丢失或功能失效：
   - 行高至少为字体大小的 1.5 倍；
   - 段落间距至少为字体大小的 2 倍；
   - 字母间距至少为字体大小的 0.12 倍；
   - 单词间距至少为字体大小的 0.16 倍。
4. 不得将固定高度、固定行数裁剪或其他排版约束作为唯一布局方式，以免用户放大文字或调整间距后发生文本截断。
5. 在适用情况下，应使用相对单位（如 `rem`）定义字号，使界面更容易适配用户的浏览器字体设置。

具体合规要求应结合产品适用的 WCAG 版本、目标市场和项目验收标准执行。

## 6. Agent 聊天界面的补充规范

对于具有对话、工具调用、执行日志及多 Agent 协作能力的产品，应采用清晰、稳定的文本层级。

| 界面元素               | 建议字号 | 设计要求                                               |
| ---------------------- | -------- | ------------------------------------------------------ |
| Agent 回复正文         | 16px     | 作为主要阅读内容，优先保障长文本阅读体验               |
| 用户消息正文           | 16px     | 与 Agent 回复保持基本一致的可读性                      |
| 消息时间戳             | 12px     | 作为次要元数据，不得喧宾夺主                           |
| 工具调用状态           | 12–14px  | 确保执行状态、成功与失败信息清晰可辨                   |
| 工具调用参数及调试信息 | 12–13px  | 允许紧凑显示，但应支持展开和详细查看                   |
| 代码及终端输出         | 13–14px  | 结合代码密度、字体和容器宽度确定，避免默认使用过小字号 |
| 面板标题               | 18–20px  | 明确区分对话区、工具区及其他功能区域                   |

以上为建议配置。代码区、终端日志及数据密集型组件可采用独立字号规则，但不得影响关键内容的识别与操作。

对于较长的 Agent 输出，应优先通过合理的行高、内容宽度、分区、折叠和层级组织改善阅读体验，而不是通过整体缩小字号来压缩界面。

## 7. 设计验收标准

界面交付前应至少完成以下检查：

-  常规正文符合项目规定的最小字号要求。
-  核心阅读内容默认使用 16px 或经过明确评估的等效配置。
-  小字号仅用于合理的次要信息或经过批准的特殊场景。
-  字号、字重、行高和文本颜色符合统一的设计 Token。
-  普通文本及大号文本满足相应的 WCAG AA 对比度要求。
-  在桌面端和移动端均能正常阅读，不因视口变化而出现不合理的字号缩小。
-  文本放大至 200% 后，主要内容和功能仍可使用。
-  用户调整文本间距后，不会发生不可接受的文本截断、内容丢失或功能失效。
-  长文本、工具调用日志、代码和终端输出均经过实际显示检查。
-  未使用过小字号、低对比度或不必要的文本裁剪来解决布局问题。

## 8. 规范总结

项目默认采用以下原则：

- 桌面端常规正文最小字号原则上为 14px。
- 移动端常规正文最小字号原则上为 16px。
- 核心阅读内容默认使用 16px。
- 12–13px 仅用于次要信息、元数据和特定紧凑型界面。
- 小于 12px 的字号不作为常规 UI 设计方案。
- 字号必须与行高、对比度、字体、布局及无障碍要求共同评估。
- 任何字号例外均应有明确的使用场景和可读性依据。

本规范中的字号建议属于项目级设计约束；WCAG 对比度、文本缩放及文本间距要求属于独立的无障碍验收维度，不应将二者混为一谈。
