# 工作详情与执行记录审阅

原窗口宽 600px，说明、结果、验收意见和多次执行连续堆叠。工具参数内联显示，工具返回内容虽已保存，却未通过接口提供给阅读器。长报告难以找到结论，也难以分清不同执行的证据。

## 阅读结构

- 默认 1120px，可全屏阅读。标题和工作操作保留在窗口内，支持拖动、关闭、Escape 和焦点恢复。
- **成果概览**：先显示受阻原因与已记录成果，再显示说明和可跳转的前置工作。缺少结果时明确标示尚未记录成果。
- **验收与问题**：独立展示主控诊断、预期成果、验收标准、收工条件、检查意见、解决证据和编码成果入口。
- **执行记录**：桌面左侧按次选择，右侧审阅当前执行；窄屏使用执行选择框。支持搜索已载入内容、状态筛选、手动刷新及载入更早记录。
- 每次执行分为“产出与错误”“工具调用”“分析记录”。产出优先展示；工具参数与返回内容按需展开，大段参数不在折叠时渲染。

主阅读正文为 16px，代码与工具参数为 14px，时间等元数据为 13px。Markdown 复用清洗后的 `ChatMarkdown`；原文可以完整显示和复制。窄屏统一滚动阅读区，放大文字不会被固定工具栏挤掉正文。

## 数据与边界

- `WorkReview` 管理工作详情和两个独立的只读轮询；`WorkRunReader` 管理执行选择及阅读；`ReviewContent` 提供阅读控件；`workReviewModel` 负责工具配对、筛选及时间格式化。
- 执行与验收记录每 3 秒刷新。取消后的响应不会覆盖新的选择；失败保留已载入内容并提供重试。刷新不跳到新记录或重置当前长报告的滚动位置。
- 首次读取最近 20 次执行，可继续读取至接口现有的 50 次上限。搜索只覆盖已载入的记录。
- `WorkRunView.toolRounds` 增量提供已保存的工具往返，使用 `tool_call_id` 关联参数和返回内容。旧记录或旧接口只有 trace 时继续展示已有调用，并明确标示缺少返回内容；不会把“调用过”或“有返回”解释成成功。
- “本次调用结束”“已提交检查”“未提交成果”等状态保持原有含义，不据此推断工作已验收。已有讨论、干预菜单和归档只读行为保留。
- 不修改执行调度或数据库结构。后端接口更新需重启后端生效；前端兼容尚未返回 `toolRounds` 的旧接口。

- `npm --prefix frontend run test:collaboration`
- `npm --prefix frontend run test:collaboration:browser`
- 后端 `RoundtableWorkflowActivityTest`：真实返回内容保留，旧记录异常 JSON 容错。
