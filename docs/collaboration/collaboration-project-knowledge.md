# 协作项目的资料与进度

项目负责长期积累成果、决策和现状，会话负责一次有边界的推进。项目资料属于项目，不属于某个 Agent 的私有记忆。

## 用户入口

进入「协作 → 项目 → 项目资料与进度」。这里支持创建和修订 Markdown 文档、搜索标题和正文、读取历史版本、标记过期资料，以及导出当前查看的版本。

- **项目现状**：当前阶段、已完成工作、未完成与阻塞、下一步。
- **关键决策**：结论、理由、考虑过的替代方案、适用条件。
- **成果与参考**：代码/文件位置、使用方法、验证方法和限制。
- **交付记录**：正式交付时自动保存的成果、验证证据、范围、后续建议、任务结果和已解决议题结论。

资料正本保存在应用数据库 `project_document` 中。点击「导出 Markdown」才会下载 `.md` 文件；不会自动向绑定的代码目录写入额外文件。

## 新会话如何承接

同项目的成员在讨论、执行以及普通进度问答时都会获得资料索引、最近的项目现状正文（有长度上限）和当前未完成工作的记录。索引最多显示 12 份资料，未完成工作快照最多显示 10 项；成员可通过 `read_project_knowledge` 搜索、分页、读取全文和历史版本。资料不会因超过最近三次交付而不可访问。

主控通过 `write_project_knowledge` 维护资料；执行者和检查者只读资料，将新发现交回主控。项目内容是历史材料，不是新的执行授权。成员仍需核对相关文件和验证证据，不能从历史资料推断工具已执行、任务仍在运行或项目已全部完成。

## 保存和追溯

文档每次保存都追加一个版本，记录作者、更新时间及来源会话标题/标识。`expectedVersion` 不匹配时拒绝覆盖，调用者须重新读取并合并。过期资料默认不进入交接索引，但仍能显式查阅。

`manage_plan(action=finish)` 成功确认交付时，项目交付文档与计划完成状态在同一事务中保存。归档或删除来源会话不会删除项目文档；删除项目才会随之删除其资料。

应用启动时会幂等补入已有的已确认交付记录；无法从旧记录取得的信息标明未填写，不编造项目现状，也不覆盖用户修订。

当前未完成工作由实际 TODO 状态汇总，排除已归档任务；它与主控维护的项目现状文档互为补充。历史会话聊天、私有记忆和未发布思考不会因此自动成为项目共享资料。
