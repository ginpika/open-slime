# 协作页面布局与可读性审查

## 信息职责

- **项目**承接长期方向、成员、成果、关键决策与项目现状。
- **协作会话**推进一次有边界的目标，完成执行、独立检查与交付。
- **本次工作**是会话内可验证的具体工作条目；议题处理其中的局部疑问。

界面统一使用“新建会话、归档会话、恢复会话”等文案；具体工作区使用“本次工作、工作依赖”，减少会话与工作条目都叫“任务”带来的混淆。

## 布局调整

起始页用简短的三步说明交代项目、会话和成果之间的关系，保留项目列表作为主体。

项目页按“协作会话 → 项目资料与进度 → 项目设置”排列。顶部保留工作目录状态，区域导航支持直接前往推进记录、成果和设置。工作方向与成员放在设置区域，避免管理信息占满主要阅读区域。会话列表显示真实交付/暂停状态，归档和删除采用带中文可访问名称与提示的紧凑图标操作。

资料区默认读取项目现状文档，按需查阅其他文档；历史版本有明确提示和返回最新版入口。窄屏下文档列表可展开收起，优先给正文留出空间。资料来源显示成员名称或用户修订，避免直接展示内部标识。

会话页保留消息、协作图和本次工作之间的边界；顶部可直接返回项目资料。范围和验收展开后使用分栏阅读，窄屏恢复单列。目录和资料入口在窄屏使用带中文标签的图标，减少顶部换行。会话切换、消息虚拟化与应用级协作运行时继续沿用原实现。

## 字号与间距

遵循 `docs/ui-design-font-size.md`：

| 内容 | 桌面 | 窄屏 |
| --- | --- | --- |
| 页面主标题 | 32px | 28px；会话标题 24px |
| 区块标题 | 18–22px | 18–22px |
| 消息、项目现状与文档正文 | 16px | 16px |
| 常规说明 | 14px | 16px |
| 按钮、输入与菜单 | 14–16px | 14–16px |
| 时间、版本等元数据 | 12–13px | 12–13px |

协作布局采用 rem 字号和 8px 为基础的间距节奏：相邻控件通常 8–12px，区块内 16–24px，区块之间 28–32px。正文不使用固定行数裁剪；文档代码块与表格保留局部滚动。颜色、按钮形状和图标继续使用项目主题及 AppIcon。

## 验证方式

浏览器回归使用应用构建产物和模拟接口，覆盖交互及截图。审查检查四种主题、1440/850/390/320 宽度、核心字号与说明文字对比度，以及 200% 文字放大和自定义文本间距。真实模型执行与后台服务不属于这次 UI 验收范围。

检查脚本：`frontend/tests/collaboration-browser-check.mjs`。截图、字号和对比度实测记录写入 `backend/target/collaboration-browser-check/`。
