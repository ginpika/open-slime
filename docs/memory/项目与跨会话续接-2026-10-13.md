# 项目与跨会话续接

## 使用

会话输入区的省略号菜单提供：

- **新建项目并绑定**：输入名称、类型和可选简介；同名、同创作属性的活动项目会复用。
- **将当前会话整理为项目**：选择已有项目或新建。历史消息与已有记忆的归属保持原样；同一 Agent 在该项目的新会话中可读取来源会话的最近进度。
- **在新会话继续项目 / 当前会话**：保留 Agent、项目和会话配置，创建空的新会话并授权续接指定来源。没有项目时也可使用。
- **停止本会话的跨会话续接**：立即停止带入其他会话的进度。重新绑定项目恢复项目范围；明确续接某个来源只恢复该来源。

小说、剧本、角色扮演项目自动使用创作身份。项目绑定意味着允许同一 Agent 在同一项目内续接进度，不意味着所有 Agent 都能读取全部内容。

Agent 的 `manage_project` 支持 list、suggest、create、bind、continue、progress、read、revoke。主动建议只保存待确认方案，不创建或绑定项目。用户明确下达操作指令后直接执行；简短的“好 / 可以”只能确认该会话中 30 分钟内的具体方案，参数必须一致，确认后方案失效。子代理和后台执行不自动获得此工具。

## 读取与一致性

原有 MemoryPolicy 和事件读取隔离保持不变，L3 不会自动升级为共享权威。独立的续接路径检查当前会话绑定、同 Agent、同项目或显式来源授权，以及临时会话开关。归档项目、删除来源、跨项目重绑和取消授权都会影响后续读取。

续接材料是带来源会话 ID、消息 ID、更新时间的最近两轮已落库对话摘录，保留长回复开头与末尾，不调用额外 LLM，不依赖攒批提炼完成。它是历史工作材料，不是新指令或已确认事实；若需细节可按消息 ID 和字符偏移读取。当前会话的明确更新优先。

自动注入最多选择两个来源，优先显式续接来源，再按最新消息排序；独立 token 上限 `minis.memory.continuation-tokens` 默认 1800，可设为 0 关闭自动注入。启动快照保存实际选入的正文，在记忆回放页可查看；模型/工具边界重新检查授权，只保留轮初材料，撤销立即生效。

Agent 在轮内绑定项目时，本轮已建立的上下文不被重写，工具会返回可立即用于回复的进度；下一轮使用新项目作用域。本轮收尾提炼读取最新绑定，避免仍写入旧项目。

## 数据与上线

新增 `session_continuation` 和 `project_proposal` 表，由现有幂等 schema 初始化创建。没有对用户运行数据库做自动项目绑定、历史记忆迁移或身份改写。重启新版后端、刷新前端后，用户可在原会话执行整理与续接。

当前为单用户模型，沿用现有 API 的用户访问边界；未来多租户化时需要给项目、会话和授权统一加用户归属校验。

验证使用内存 SQLite 和模拟模型，不发送真实 LLM 请求。覆盖最新进度、长回复末尾、项目/Agent 隔离、历史归属保留、授权撤销、临时会话、项目归档、来源删除、分页读取、具体方案确认、事务回滚和快照回放。

按用户要求，最终验收由用户执行。此前前端构建与既有记忆前端测试通过；后端完整检查曾在新增“删除来源”用例中因测试未先清理消息而触发外键错误，已修正清理顺序，修正后未重跑。浏览器验收工具无法连接本机预览，未完成界面交互验收。
