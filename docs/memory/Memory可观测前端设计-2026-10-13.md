# Memory 可观测前端设计与验收标准

本任务目标：让用户看见所有 Agent 的记忆归属、真实读取边界、来源、生命周期和执行使用情况，并能控制它们。设计基于四层 Memory 大纲及当前后端权限规则。

## 现状评估

现有 MemoryPanel 有条目、画像候选、共享、泳道、工作集、体检、时态查询和发布八个标签，管理动作已经较完整，但存在以下学习与观测障碍：

- 只显示 L1/L2 标签无法回答谁能读；L1 项目事实并非全局，L2 私有归属也可能被显式发布。
- 项目、Agent、会话多数以 ID 表示，没有贯穿页面的观察上下文。
- 没有以真实 MemoryPolicy 为依据的 Agent 读取视角。
- 快照保存在后端，但没有回放入口；库里有某条记忆不代表本次调用用了它。
- 来源、作者、证据、版本、有效期和修改审计没有统一的条目详情。
- 体检/运行计数不等于记忆质量，旧页面容易把错误加载解释成空数据。

## 信息架构

新增观测层，保留原管理能力，主导航精简为四个问题：

1. **记忆全景**：系统保存了什么，四层如何分工，哪些处于用户全局、项目、Agent 或任务范围。
2. **Agent 视角**：选择 Agent、项目及会话/任务，由后端真实权限谓词返回当前可读条目与原因；同时区分“属于它”和“它能读到”。
3. **运行回放**：选一次执行，查看启动快照中的原始版本与工作集；有真实调用留痕时，再显示每次调用发出的记忆段。
4. **治理工作台**：候选审批、受控确认、发布/撤销、交接、工作集收尾、时态与恢复等现有动作集中在这里。

全景和 Agent 视角共用可检索的记忆目录及详情面板。按层级、归属范围、内容域、项目、Agent、身份、状态筛选；正文搜索在已加载目录中进行；目录卡片分页，每页 25 条。

## 必须讲清的概念

| 概念 | 页面表达 |
| --- | --- |
| Owner：记忆归谁管理 | 用户、项目、某个 Agent、任务；不能从产生者推断归属 |
| Domain：描述什么 | 用户画像、项目内容、Agent 经验、事件/任务 |
| Layer：如何使用与流转 | L1 受控共享、L2 私有积累、L3 任务材料、L4 显式发布 |
| 可见范围 | 按归属及发布授权组合描述，标明项目/会话限制；失效条目不表示仍可读取 |
| 身份 | 现实、虚构、项目偏好、推断；虚构来源不等于现实用户画像 |
| 存储与使用 | 保存条目 → 当前有权读取 → 检索选入启动快照 → 实际调用携带记忆段；四者不能混为一谈 |

图形使用四层卡片、流转步骤和 Agent 对比条；颜色只辅助辨认，并始终配文字。沿用项目主题令牌，兼容深浅主题与窄屏。

## 条目详情与用户控制

详情必须展示完整正文、归属者与产生者、层级/领域、当前读取范围、身份、证据文字、来源引用、版本、保留策略、有效期、发布接收方、近期快照选入次数及修改审计。

详情提供固定/取消固定、版本化编辑、定向发布、撤销发布和遗忘。操作前显示具体条目和影响范围；执行成功后重新读取服务端状态。将遗忘与不可恢复清空区分，批量维护保留在治理区。

画像候选与共享事实明确“待用户确认”。不能暗示模型置信度是实测准确率，也不能暗示发布等于事实已被验证。

## 后端补齐范围

只补前端观测必需的只读能力，不发起提炼/embedding 调用：

- 按执行上下文读取可见集合及读取原因，复用 MemoryPolicy/MemoryItemStore。
- 列出和读取已存快照；新版快照显示当轮版本正文，旧引用快照明确标记无法完整回放。
- 在可用时关联已有模型调用留痕，仅提取实际请求中的 Memory 段；缺记录时明确说明，不能用启动快照冒充实际请求。
- 补齐条目来源/产生者等展示字段，复用既有修订审计接口。

## 效果评估方法

提供可操作的观察路径：在会话中明确要求记住一条信息 → 检查候选/归属及证据 → 必要时批准 → 查看该 Agent 的读取范围 → 发起后续任务 → 在运行回放中核对是否选入及实际携带 → 对照回答检查是否正确使用。

首版指标只描述事实：有效/失效条目、未发布私有条目、有效发布条目、待确认候选、近期快照数量与选入频次、预算淘汰及权限拦截计数。快照统计明确时间窗口/上限；进程计数明确重启清零。

这些指标帮助定位效果问题，不自动给出“Memory 准确率”或“Agent 已学会”的评分。需要回答质量的评测仍由实际测试任务及用户反馈确认。

## 验收场景

1. 用户一眼区分全局画像、项目共享、Agent 私有、任务材料和定向发布。
2. 不把项目 L1 标成全局，不把已发布 L2 标成绝对独享。
3. 选择两个 Agent 可观察到私有读取差异，来源为后端权限结果。
4. 项目/会话/任务上下文影响 L3 与项目私有范围，未指定上下文时有说明。
5. 查看条目可从正文走到证据、授权、版本和审计，操作有具体目标与影响提示。
6. 能打开一次运行的启动快照并查看历史正文；有调用留痕时能对照实际发送内容。
7. 删除/撤销后的历史快照保持历史事实，当前状态另行标注；旧快照、记录缺失不补造。
8. 加载失败显示可重试错误，不以零条目或“正常”掩盖失败。
9. 无数据、没有匹配、部分接口不可用、慢请求和快速切换上下文都有明确状态。
10. 前端类型/生产构建通过；后端权限观测与快照接口有回归测试；用浏览器检查宽屏与窄屏可操作性。

用户授权范围内直接实现和验证，本文件作为本任务的标准；完工后补记实际交付与验证结果。

## 实际交付（2026-10-13）

- 主导航新增「记忆」，直接打开 `#/memory`；沿用所有主题与桌面侧栏共用的 NAV 数据源，并注册页面路由与主题插槽。原「智能体 → 系统 → 记忆」入口保留。新增全景、Agent 视角、运行回放、治理四个主视图；原八个管理视图保留在治理区。
- 全景提供四层卡片、六类范围统计、全部已登记 Agent 与历史归属 Agent 的分布地图。全景数字标注全库 / 最近窗口；筛选后的目录不冒充全库统计。
- Agent 视角展示后端真实可读集合、可读原因与 Agent 编辑权限；工作材料复用运行时 WorkingSetService。选择已登记会话时自动带入其 Agent 与项目，也可手动组合上下文研究访问边界。
- 条目详情集中正文、Owner / Domain / Layer、生产者、项目与绑定、身份、原文证据、期限、版本、取代 / 提升来源、发布授权、审计及最近快照选入次数。固定、编辑、定向发布、撤回、遗忘在详情操作；编辑提交打开表单时的版本号，防止覆盖并发修改。
- 回放显示完整启动快照的历史正文与工作集、与当前版本 / 状态的对照，以及已有真实请求中提取出的 Memory 段。普通预算用量明确不含保护条目，不等于实际请求总 token。
- 非会话独立执行目前通常没有可关联的逐次 LLM 请求留痕，界面明确说明；没有把启动快照宣称为最终请求。旧版或损坏快照只显示已保存引用，无法恢复的正文不补造。
- 读取部分失败显示具体错误；无数据、没有匹配、无权限结果及接口失败分别表达。观察读取 15 秒超时，可重试。快速切换上下文时丢弃过期请求结果。授权读取失败时不将条目直接宣称为独享。
- 详情使用主题令牌和响应式布局；以 portal 挂到 body，避免现有玻璃 / 裁切容器截断。支持 Escape、焦点循环及关闭后恢复焦点。
- 观察接口均为只读，不提炼、不调用模型、不生成快照，不改变用户的 Memory 数据。

**浏览器宽窄屏、深浅主题和实际点击验收尚未完成。** 沙箱内 Vite 服务无法被浏览器连接；在沙箱外启动本机隔离服务的请求未获批准。因此响应式和交互已实现并完成静态 / 类型检查，但不能声称完成浏览器验证。未启动真实后端、未迁移或写入实际数据库。


真实数据验收需要运行更新后的后端以提供 `/api/memory/observation/*`，刷新前端后点击主导航「记忆」或直接打开 `#/memory`。建议优先按“画像候选 → Agent 可读范围 → 运行回放 → 回答表现”观察同一条测试记忆。

## 第二轮 UI 评估与优化

评估结论：四个主视图围绕“存了什么、谁能读、如何使用、如何控制”划分合理，第一版在组件复用与信息密度上不足。

| 发现的问题 | 采用的措施 |
| --- | --- |
| 原生 select 的菜单不能随主题定制，也未复用项目现有下拉 | 统一走共享 Tailwind Select，保留 formKit 原出口兼容设置等页面；增加名称 / ID 搜索、方向键 / Enter / Escape 操作、选中标记、标签及禁用状态 |
| ui-control 被直接挂在 input / textarea 上，无法正确绘制主题伪元素 | 改用 Kit.Field / Control 外壳，统一控件高度、描边与焦点样式；包括详情编辑及治理表单 |
| 全景所有区块竖排，Agent 多时无限拉长页面 | 范围与 Agent 地图宽屏并排；归属列表有限高滚动；层级卡片更紧凑；架构说明、工作材料与质量说明渐进展开，信息保留 |
| 七项筛选同时展开，容易混淆“查看范围”和“运行时上下文” | 上下文独立成区并解释影响；目录主栏只放搜索 / 层级 / 范围 / 状态；Owner / Domain / Identity 收进更多筛选，选中条件作为可单独移除的标签 |
| 治理八张入口卡与内层八个标签重复 | 改成一套治理模块选择；嵌入管理组件时隐藏重复标题和导航，整理 / 清空只放条目管理 |
| 长详情中操作藏在底部，元数据与证据抢占阅读顺序 | 固定详情标题与操作；正文、归属和证据优先；生命周期与来源细节折叠；操作表单靠前，未选择发布目标时禁用提交 |
| 页面自行规定标题 / 指标 / 字段 / 徽章外观，与其他页面不一致 | 复用 usePageKit 的 Page / Toolbar / Panel / Stat / Field / Badge / Empty，以及共享 Button；页面 CSS 只承担 Memory 图形和布局 |
| 卡片裁切 / 滚动容器可能截断自绘下拉 | 下拉弹层使用 portal，按视口空间向上 / 向下展开并限制宽高；对话框内保持 DOM 归属，参与已有焦点循环；Escape 优先关闭下拉 |

同时修正共享 Button 组件缺少 `ui-btn` 基底类的问题，默认 `type="button"`，避免普通动作隐式提交表单。刷新按钮放在始终可见的 Toolbar，兼容会隐藏页眉的侧栏主题。

新增 5 项控件测试验证长目录搜索、键盘边界、窄视口弹层定位、旧 formKit 出口 / 无障碍静态结构，以及标准按钮类型与样式。连同原语义测试共 10 项，均通过。静态渲染与位置算法测试不替代浏览器中实际点击、焦点、裁切及深浅主题截图验收；后者仍待运行环境允许后完成。
