# Memory 架构修复说明

本次按《Memory架构审查-2026-10-12》列出的顺序修复后端，并接通必要的记忆管理入口。保留四层模型和统一存储，重点修正各入口实际执行的隔离、治理与生命周期规则。

## 12 项偏离对应的措施

| 审查问题 | 采用的措施 | 修复后的行为 |
| --- | --- | --- |
| 1. 事件召回绕过作用域 | 事件新增 Agent、项目、会话、任务、身份元数据；写入显式传递上下文；事件检索在 SQL 中按会话/任务或同域后台归属过滤 | 原始事件也受隔离约束；无归属历史事件只供人工审计 |
| 2. PROJECT 读取吞掉层级边界 | 拆开 PROJECT 的层级谓词：L1 同项目共享，L2 同项目同 Agent，L3 同会话/任务，L4 必须命中显式发布授权；Agent 的项目私有经验也限定项目 | 同项目不再等于可读取全部私有、临时或定向发布内容；撤销 L4 发布后不可再绕过授权读取 |
| 3. 项目共享写入不受控 | 自动事实、决策和进度先落 L3；方法与未解决事项落 L2；普通 Agent 禁止直写/改写 L1 和已发布 L4；新增人工确认项目事实入口，检查来源、版本、期限和同名冲突 | 共享权威来自明确确认；自动提炼不能直接变成所有 Agent 依赖的正式事实 |
| 4. 画像审批与证据断开 | 将真实用户消息引用与原话贯通到提炼；模型只能选择能在用户消息中核对的原话；候选合并独立引用、保留有效期；审批检查真实来源、证据、期限、墓碑和同名冲突 | 用户明确陈述可以形成可审批候选；重复提交同一引用不伪造多次证据；创作/项目偏好只能留在项目域 |
| 5. 保护项提前被检索淘汰 | 独立 SQL 查询正式画像、指令、pinned、open_issue，再合并普通候选；保护项豁免向量门控和普通结果条数裁剪；注入渲染与预算使用同一正文截断规则 | 无 embedding 或普通候选超过 200 条时，正式画像和规则仍进入执行视图 |
| 6. 情景配额跨域挤占 | 按 Owner、Domain、Project、Agent、Layer 分组；L3 进一步区分会话/任务；长期保留和保护项不参与普通情景配额淘汰 | 小说项目新增情景不会消耗其他归属的保留名额；已确认共享与发布知识不被后台语义巩固自动改写 |
| 7. 遗忘后自动重建 | 自动提炼、普通自动写入和新发布共用墓碑检查；遗忘/批量撤销增加事务，并撤销相关共享；收件箱复核有效性 | 同指纹内容不能被自动学习或发布回来；遗忘内容不会留在有效交接入口 |
| 8. 正文、指纹、向量不同步 | CAS 更新同步重算指纹、记录完整前后正文、删除旧向量；向量保存校验条目版本；修复缺向量查询字段并接通补齐工具和定时重试；事务内补齐延至提交后 | 旧异步 embedding 无法覆盖新正文；人工新增、编辑、模型切换和失败欠账都有补齐路径 |
| 9. 生命周期绑定 Turn | 普通聊天轮末只保存检查点；明确结束会话工作或独立执行完成时才收尾；子任务只整理自己；蒸馏使用中间状态，成功才关闭，失败恢复，重启恢复未完成蒸馏；记录关闭水位，防止延迟提炼重新打开旧 L3 | 暂停和多轮工作保留工作集；任务/会话收尾有明确边界；L3 指纹及巩固键包含会话/任务，不跨任务去重 |
| 10. 子代理丢失项目与身份 | 派发时捕获完整 MemoryExec，在请求组装、异步执行及重跑时传递；独立执行绑定真实 taskId；并行工具线程继承记忆与 Agent 作用域 | 小说子代理保持 FICTION 和项目绑定，不能把创作经验写成跨项目的真实用户信息 |
| 11. 交接未闭环 | 收件箱检查条目状态、期限和具体共享授权；新增 manage_handoff 工具，支持列出、接受、拒绝、完成；按接收方鉴权，状态更新使用 CAS，完成前须先接受 | Agent 可主动跟进交接；撤销/过期内容不再被发现或接受；旧交接不因列表分页上限而失去状态操作权限 |
| 12. 快照与多表治理不完整 | 保存条目版本、完整正文、工作集及执行作用域；使用变更审计水位；普通内容沿用轮初视图，权限、撤销和指令在模型/工具边界重新校验；批准、发布、交接、提升增加事务；提升复核来源层、状态、证据、组合矩阵与版本 | 可恢复新版快照当时的记忆正文；必须立即生效的规则和权限变化在下一次调用前更新；失败不会留下半发布状态 |

关键实现集中在 `MemoryPolicy`、`MemoryItemStore`、`MemoryEvidence`、`MemoryExtractor`、`UserProfileService`、`MemoryPublisher`、`WorkingSetService`、`MemoryLiveContext`，以及聊天/子代理/执行运行时的作用域传递。

## 用户能操作的流程

记忆页增加了三个实际入口：

- **确认项目事实**：把有来源的 L3 项目事实确认成 L1。版本变化、来源缺失、已过期或存在同名矛盾时拒绝确认。
- **查看画像原话证据**：审批前可查看真实用户消息的证据文字和有效期。
- **结束会话工作并整理**：显式提交工作集蒸馏。普通对话回复完成和暂停不调用此入口；提炼失败保留工作项供重试。

编辑记忆现在必须携带读取时的版本。管理页已同步携带该版本；版本冲突返回 HTTP 409，避免静默覆盖。

Agent 增加 `manage_handoff` 工具。L4 是显式分享的信息，仍保留推断/虚构来源标签；发布动作不等于自动认证为 L1 的权威事实。

## 旧数据如何处理

增量结构补丁为现有表加列，数据迁移版本提升到 **v4**。本次没有启动应用，也没有对实际运行数据库执行迁移。

下次应用启动时，对文件数据库先备份，再在事务内执行数据迁移。备份失败时停止迁移。内存测试数据库不需要文件备份。

- 历史事件缺少可靠作用域时，不根据当前会话绑定猜测它原来属于谁，继续保留供人工审计。
- 旧的自动项目共享事实降到有绑定的 L3；无可靠绑定或私有作者归属的条目归档，等待人工复核。
- 重新计算发生作用域变化的指纹，并对应调整撤销记录。
- 缺少内容版本标记的旧向量投影移除，随后重新补齐；记忆正文保留。
- 旧快照没有记录完整版本正文，无法凭新增字段补出当时的真实上下文。完整回放能力适用于新版快照。

## 验证

完整后端测试通过：**222 项，0 失败、0 错误**。其中新增架构回归 17 项、迁移回归 1 项，覆盖实际 SQLite/schema，包括：

- 项目 L2/L3/L4 隔离、事件隔离、撤销发布后失效；
- 保护项在无向量和候选洪流下保留，分域情景配额与长期保留；
- 跨会话同正文不误去重，改写后的指纹/向量版本一致性；
- 真实用户证据与候选有效期、自动提炼遵守遗忘墓碑；
- 已确认共享不可由 Agent 覆盖，交接权限、状态机与事务回滚；
- 不可变快照与实时规则刷新、蒸馏失败恢复、延迟提炼防止重开旧会话；
- 子任务不收尾父会话、子代理及并行工具保持 FICTION 身份；
- v4 迁移保留无归属历史并降级未确认事实，重复执行幂等。

前端 TypeScript 检查和 Vite 生产构建均通过。构建仍有现有的大包体积提示，不影响本次构建成功。

后端验证使用本地依赖离线执行，并在测试 JVM 启动时加载 Byte Buddy agent，避免动态附加导致测试挂起。

## 仍需明确的边界

代码边界与确定性行为已有回归验证；本次没有向真实 LLM/embedding 服务发送请求，也没有用生产记忆数据评估提炼质量。

同名同作用域的矛盾会被阻止；不同措辞、不同标题之间的语义矛盾仍由人工确认流程判断。自动输出保留候选/推断语义，不直接覆盖共享权威。

实时校验在下一次模型调用或工具执行前生效，无法撤回已经发出的那一次模型请求。普通内容继续使用本轮启动时的快照，下一轮读取最新版本。
