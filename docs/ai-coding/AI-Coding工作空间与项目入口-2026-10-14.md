## 使用流程

1. 进入“编程”，首先看到项目起始页，提供“新建项目”和“打开项目”。
2. 选择现有已启用的工作空间，在目录浏览器中选择父目录或项目目录。
3. 新建项目时输入名称，在选定父目录创建一个新文件夹；打开项目时直接绑定选定目录。无需填写后端宿主绝对路径，也不要求该目录已经初始化 Git。
4. 进入项目界面，顶部固定显示项目、工作空间和相对目录。左侧是文件树与项目任务，中央是文件预览、代码差异与命令输出，右侧是 Agent 对话与任务输入。
5. 可以在“项目目录”与“当前任务副本”之间切换文件来源。代码预览是只读的；当前修改由 Agent 的补丁工具完成。
6. 分析 / 修改 / 执行模式保持原有权限含义。执行模式使用项目绑定的工作空间环境，不再让用户为项目重新配置另一套 Docker/SSH 连接。
7. Agent 收尾后查看差异，确认后再应用到原项目目录。应用时再次检查快照、产物哈希、文件冲突和链接边界。

工作空间页的目录工具栏新增“编程”跳转，携带当前工作空间与相对目录。项目界面也能返回同一个工作空间。`#/coding` 总是起始入口，`#/coding?project=<id>` 打开项目，任务链接继续支持 `run` 参数。

## 后端接线

| 组件 | 变化 |
| --- | --- |
| `coding.workspace.WorkspaceProjects` | 复用工作空间身份；打开/创建目录、绑定项目、浏览文件、传输快照、执行前后同步、接受变更 |
| `coding.workspace.WorkspaceArchive` | 有界二进制归档传输，拒绝越界/链接/重复条目，保存可执行位 |
| `coding.runner.WorkspaceCommands` | 复用 ExecTarget 运行命令，使用独立任务目录和进程组，支持查询、停止、恢复与审计 |
| `ai.terminal.TerminalService` | 暴露既有命令规则与执行上限；Coding 不自行复制白/黑名单规则 |
| `CodingWorkspace` | 在后端建立可信 Git 基准，用于补丁与 Diff；工作空间项目无需先建 Git 仓库 |
| `CodingFacade` | 根据项目绑定自动选择 WORKSPACE 路线；冻结/同步进程后生成交付哈希 |
| `coding_workspace_project` | 新表保存仓库 ID、工作空间 ID、相对目录、规范路径与连接配置指纹；不复制连接凭证 |

新增 API 为 `/api/coding/workspaces`、`/projects`、`/projects/{id}/files`、`/projects/{id}/file`。打开/新建项目由 `POST /projects` 完成；文件接口的可选 `runId` 用于查看本项目的任务副本，并校验任务所有者和项目归属。

打开/新建工作空间项目与既有工作空间接口一样要求应用登录，不额外要求 SSO 管理员。项目归属由服务端会话确定；SSH 用户（包括 root）只决定远端文件/命令权限，与应用登录角色无关。旧后端宿主路径登记接口仍要求管理员。本次没有新增工作空间级用户 ACL，仍复用现有工作空间访问模型。

工作空间返回的是精简 DTO，不包含 SSH 密码、私钥或 Docker 连接凭证。目录选择和命令执行要求工作空间已启用，绑定后连接定位字段改变则拒绝继续，避免误操作另一个环境。旧本地仓库 API 和任务数据保留，但起始页只列工作空间项目，旧本地任务不会被静默迁移成远端目录。

## 执行与应用契约

文件源位于选定 Docker / SSH 环境。后端通过现有 ExecTarget 获取项目快照，本地副本用于工具读写和 Diff。执行模式将副本同步到工作空间的 `.minis-coding/<run>/<attempt>/checkout`，使用该工作空间已有工具链与权限执行命令，结束/停止后同步代码回来。依赖与构建目录不进入交付快照；任务目录同步保留已经安装的依赖及输出。

同一任务一次运行一个工作空间命令，后台进程以独立进程组启动。启动前保存进程记录，远端原子保留执行目录，重复受理不会再次启动命令。停止检查进程身份和进程组中的实际活动进程，保留无法确认的中断状态。后端重启后恢复会先停止旧任务进程，并同步旧 attempt 的文件，而不是重放未知操作。

命令沿用工作空间启用开关、原文白/黑名单、超时与输出上限；完成结果进入现有终端审计和 Coding 事件。可信文件传输操作与既有人工文件浏览一样，不使用模型命令白名单；模型提供的命令必须先通过既有规则。

应用变更前核对原项目基准文件内容与可执行位，新增文件检查重名。远端应用脚本预检查所有路径，用日志和备份进行异常回滚；成功记录含已审阅哈希的收据，丢失响应后可以确认同一收据，不重复写入。中断结果未确认时保留本地/远端接受日志，拒绝盲目继续。

当前传输要求 Linux/POSIX 工作空间提供 `sh`、`tar`、`base64`、`mktemp` 等工具；执行与接受变更还需要 GNU `timeout`（含 `--foreground`）、`setsid`、`ps -eo`、`awk`、`sha256sum`、`stat -c`。缺少工具会返回实际失败，不自动在线安装。单次压缩传输上限 16 MiB，解压快照上限为配置值与 64 MiB 的较小值。超大项目需缩小所选目录或后续升级传输协议。

WORKSPACE 复用现有环境权限，任务目录副本提供代码交付边界，不能视为额外的操作系统沙箱。传统后端 Docker Runner 仍用于旧本地仓库路线；后续若需要强隔离，可在现有工作空间域上增加专用 Runner 协议。
