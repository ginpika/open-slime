# 经济：三图隔夜策略

经济起始页提供「隔夜策略工作台」(`/economy/research`) 与「观测数据库」(`/economy/database`) 两个独立入口。大盘和个股仍在同一工作台右侧选择，左侧是同一个可操作浏览器或已打开窗口。旧的 `/economy/market`、`/economy/stock` 链接统一进入 `/economy/research`。新页面通过共享导航契约生成标题、全局归属与「经济 → 观测数据库」面包屑。

更新后需重启后端以初始化新表；桌面版需重新构建，使原生窗口观察权限识别新的工作台路由。

## 用户流程

1. 选择大盘或个股、标的、观测日期、分析 Agent。
2. 在浏览器或软件中进入周线界面，点击「周线分析」。保存当时的截图，再对这张图分析。
3. 切到日线，点击「日线分析」，保存新的截图与日线分析。
4. 切到当日分时，点击「分时分析」，保存分时截图与分析。
5. 点击「提交三图总结」，把已经保存的三张截图与分步分析一起发给 Agent，生成并保存总结报告。

分析按周线 → 日线 → 分时推进。每一步可以重做，新截图新增记录，既有总结仍引用提交时的版本。模型失败不丢截图，可「重试已保存截图」；服务重启后未完成分析标记为可重试。刷新页面恢复本轮观测。桌面布局左右独立滚动，窄屏使用单列并保留可用内容宽度。

工作台右侧固定显示三步进度与总结入口，点击可跳到对应步骤。首次保存截图后自动收起观测设置，摘要保留标的、日期和 Agent；选填资料、网页文字输入及来源帮助按需展开。报告先展示进场/隔夜结论、五档评分和分项依据，再阅读完整分析、引用截图与收益试算。Agent 正文使用16px，支持窄屏和200%放大。

分析、截图重试与总结提交的加载状态显示在当前按钮内：原图标切换为旋转图标，保持原按钮文字与宽度，使用 `aria-busy` 标记忙碌并防止重复提交。上方来源栏不再显示分析中的进度提示；请求结束或失败均停止动画，失败说明与已保存的分析结果仍正常展示。减少动态效果设置下不旋转图标。

工作台与数据库的所有下拉框统一复用共享 Tailwind `Select`，包括标的类型、Agent、原生窗口、查询类型与两页的总结版本；Agent、窗口和版本列表支持搜索。弹层挂到浮层容器，避免被独立滚动面板裁切，保留键盘导航、Esc关闭与焦点恢复。页面、左右面板、数据库列表/详情、补充资料文本框及下拉菜单统一使用共享 `scrollbar-slim`，随主题切换深浅色。

## 唯一策略

只评估两个问题：是否具备进场条件；是否适合本交易日尾盘买入，并在下一交易日开盘后立即卖出。不扩展为做空、多日持有或其他交易策略。

分步分析先检查截图标的、周期、日期和可读性，说明观察、技术理由及缺失信息，不直接给出单图买入结论。总结再次联合核对三图，结合早于本次交易日的既往观测摘要，以及可选的基本面/事件检索，评估三周期一致性和隔夜风险。

机会评分为周线环境 25 分、日线结构 30 分、尾盘分时 30 分、隔夜执行风险 15 分。分项由模型说明，服务端校验并加总。五档仍是 0–19、20–39、40–59、60–79、80–100，分别表示机会很低、偏低、中性、较高、很高。评分不是统计获利概率；0/100不表示绝对结果。

总结按用户通常在最后一个交易小时内决策的场景，基于截图各自的数据截止时点立即给出四项评分，以及进场、尾盘买入两个问题的“是/否”。未收盘K线、未来走势未知、未显示的辅助指标或缺少基本面检索只计入限制与风险，不单独导致截图证据无效，也不能要求等后续突破、站稳、放量或收盘后再决定。条件说明逐项解释当前已满足、未满足或无法核实的状态，买入后的撤销规则不代替本次决策。

错图、日期不符或画面无法辨认仍标记证据缺口。所有新总结都必须包含四项有效评分；有缺口时仅对可核实的有利条件给分，服务端保留评分并明确不进场、不买入。低于60分或进场判断不符合时同样不能给出尾盘买入结论；达到60分不强制买入。最终模型的乐观结论不能覆盖这些服务端约束。新报告仅输出ENTER/AVOID和BUY_CLOSE/AVOID；兼容旧模型返回的WAIT时统一转成当前“否”的决策，历史报告的WAIT和空评分保留原样供回看。退出计划由服务端固定为下一交易日开盘后立即卖出。收益试算也只服务于这一个尾盘买入/次日早盘卖出情景，输入价格仍是用户假设。

提示词与校验调整需重新构建、重启后端后生效；新报告使用新规则，已有记录不自动重写。旧提示词下被标记证据不足的分步结果需重新分析，再提交总结，避免沿用旧标记导致本次仍判定不买入。

## 小型经济数据库

复用应用现有 SQLite，在 `economy/schema.sql` 中独立维护模块表，不引入额外数据库服务。

| 表 | 职责 |
| --- | --- |
| `economy_instrument` | 当前用户的大盘/个股标的身份，同类代码忽略大小写复用 |
| `economy_study` | 标的某个观测日期的一轮工作，可一天多轮 |
| `economy_observation` | 周线/日线/分时的不可变截图、SHA-256、来源、时间、Agent、模型、补充和分析状态/结果 |
| `economy_evaluation` | 三图总结的独立版本、策略版本与进场/隔夜判断 |
| `economy_evidence` | 将总结绑定到当时提交的三个截图记录 |

图片以 JPEG/PNG 原始字节存入 BLOB，元数据查询不携带图片；预览按需认证读取，禁止缓存。原始图片会随观测积累占用数据库空间。独立「观测数据库」页可按标的类型、名称、日期范围查询，分页遍历完整历史；提供筛选重置、日期校验、空状态、读取失败重试。工作台不再加载记录列表。

选择一轮后，在数据库页内读取全部分步分析、原始截图与各版本总结；可回看重做前的证据，无需打开工作台。详情的「继续本轮观测」使用会话状态交接到工作台，恢复该轮标的、日期、最近补充资料及仍可用的原 Agent，且不自动触发分析。新建观测清除本轮交接状态，不删除已有记录。`StudyResults` 复用只读分析与报告展示，`EconomyResearch` 继续独立负责采集与分析操作。

旧 `economy_report` 单图记录保留，只供历史阅读，不被当作三图策略证据，也不自动转成新策略结论。

## 应用与接口边界

- `EconomyStore` 管理身份、图片与记录的持久化、用户归属和查询；多表写入使用事务。
- `EconomyService` 负责分步顺序、冻结截图、模型调用、三图约束与策略门槛。同一轮同时只允许一个分析操作；不在模型网络请求期间持有数据库事务。
- `POST /api/economy/studies` 创建一轮，`GET /studies` 查询历史，`GET /studies/{id}` 恢复完整观测。
- `POST /studies/{id}/observations` 捕获并分析一步；`POST /observations/{id}/retry` 只重试已保存的失败截图；`GET /observations/{id}/image` 按归属读取图片。
- `POST /studies/{id}/submit` 只接收三个观测ID，不重新截图。服务端拒绝缺图、重复ID、周期缺失、未完成分析、不同轮次、不同用户的混合证据。
- 模型调用沿用所选 Agent 的身份提示词和绑定模型；图文资料只进入用户级消息。三个分步请求分别携带一张图，最后总结携带那三张原图。用量来源为 `economy-step-analysis` 和 `economy-analysis`。
- 基本面仅在总结时按已有 RAG 检索开关执行，保留失败、未启用和零结果状态。历史日期不得使用之后的信息；历史观测摘要限3条、每条2000字符。
- 浏览器截图由服务器按当前用户浏览器归属获取，窗口截图限制约3MB、2000万像素且不超过60秒。保存后的历史截图不受60秒限制，重试与总结不重新采集。

经济浏览器继续支持点击、双击、拖动、合并滚轮和中文输入，独立允许公网写请求与校验后的WebSocket；原有Agent/知识浏览器仍是只读路径。Windows/macOS窗口观察与网页版单窗口共享在停止或离开页面时释放采集。

页面记住本次会话的来源选项。桌面窗口只保存窗口ID、进程ID与恢复意图，重进时自动刷新列表，原窗口仍可用则重新采集实时预览；手动停止后不再自动恢复。观察中可以更换窗口，原窗口关闭或最小化时提示重新选择。网页版离开时结束系统共享，重进后需再次点击「选择共享窗口」；共享中可直接「更换共享窗口」。取消选择、采集失败和离开后才返回的旧共享请求均会释放资源，不会留下不可用的选择状态或旧预览。

- `npm --prefix frontend run build`

- 后端 `EconomyServiceTest,LayeringTest`：22项，覆盖图像实际入库、单图分步、最终三张原图、不可变版本、顺序、混合证据拒绝、失败重试、重启恢复、用户隔离、跨页查询、策略门槛、证据有缺口时保留评分并明确不买入，以及旧模型WAIT响应归一为当前否决策。
- `npm --prefix frontend run test:economy:browser`：覆盖独立数据库路由/刷新、筛选/分页/重置/空状态、日期校验、列表与详情失败重试、历史版本绑定原图、未完成观测交接、工作台不读取数据库列表、进度跳转、三步分析与重试、最终提交版本、旧报告、独立滚动、手机/200%放大、自定义文本间距和深浅色关键文本对比度。窗口回归包含观察中切换、离开后释放与重进恢复、停止后不自动恢复、窗口消失、截图失败、共享取消重选、旧结束事件与延迟共享返回。截图存放在 `backend/target/economy-browser-check/`。
- Windows桌面通过 `cargo check`，新增工作台路由沿用原生命令来源检查。原有截图边界测试保持可运行。

浏览器页面测试使用模型/服务夹具，后端用真实SQLite与模型协议夹具；这些检查不证明真实模型的判断质量或策略收益。TradingView线上登录、行情、真实Windows行情窗口和macOS权限/运行仍需对应环境实测。
