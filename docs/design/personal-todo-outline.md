# 待办：个人事项与精力记录 · 设计草案

状态：第一版业务模块已按此方向落地，入口 `/todos`，数据通过后端 API 持久化。本文保留设计依据；独立 HTML 仍是用于讨论的原型，所有事项和时间均为示例，不是正式页面的数据源。实际接口与边界见 `backend/src/main/java/cc/ginpika/minis/todo/README.md`。

## 1. 产品定位

主语永远是「我」：我还有什么想做、今天选择做什么、精力实际去了哪里、过去留下了什么。

模块在现有应用导航中叫「待办」，嵌入现有 AppShell 的页面内容槽位。模块不创建独立品牌栏、侧边导航、用户菜单、面包屑或第二套应用外壳；页面标题与操作沿用 PageKit，颜色、字体和形状继承现有主题令牌。项目是可管理的工作对象，具有总览与详情；事项可选关联项目，没有项目归属也完全成立。

日常操作遵循「随手记下 → 选一天 → 开始投入 → 完成或放下 → 回望」。不要求每个想法立刻明确日期、工时或优先级。

## 2. 五个视图

### 今天：我准备把精力放在哪里

- 页面顶部横向页签：今天、全部待办、项目、时间分配、回望。全局导航由现有应用外壳负责。
- 中间主区：随手记入口、项目筛选、今天选中的事项、今天完成的事项。
- 右侧：当前计时、今天实际投入的时间分配、逐条投入记录、一天的一句话回顾。这是页内辅助信息区；窄内容槽位下收至列表后，不再增加任何导航侧栏。
- 今天的列表是主动选择的结果。没有完成的事项留有原日期标记，可选择「移到今天」或「暂不安排」，不静默修改计划、不无限自动堆积。
- 已经过期且未完成的计划出现在今天顶部的小提醒里，可批量处理；没有硬截止日期的想法不会被标成逾期。
- 「计划做」与「实际做」分开。没列入今天的事也可开始计时，发生过的投入如实出现在今天。

### 待办：所有尚未结束的事

- 单一列表按「进行中」「准备做」「想法」分组。想法不强制拆解成项目。
- 项目筛选仅在「今天／全部待办」显示并在两者之间保留；筛选状态显式展示，可一键回到全部。项目、时间分配与回望不受该筛选影响。
- 快速录入只必填标题；详情按需填写备注、项目标签、计划日期、真实截止日期。
- 点击事项打开详情，查看产生、首次投入、每次投入、完成与重新打开的历程。
- 「放下」是带可选原因的结束状态，保留尝试和投入，和「完成」分别统计。
- 可以重新打开已结束事项；原完成事件保留，但不会凭重复勾选增加完成数量。

### 项目：我在推进哪些目标

- 总览以项目名称、状态、分类、目标说明为主；完成事项数与累计投入为辅助，不将事项数量当作项目完成率。
- 支持按名称和说明搜索、状态与分类筛选；主操作为「新建项目」。未关联事项单独提供入口，不作为虚构项目计数。
- 点击项目进入详情，展示目标说明、状态分类、累计投入与成果摘要、创建和最近更新时间；编辑可保存名称、说明、既有分类与生命周期状态。
- 「查看待办」跳到带该项目筛选的「全部待办」。项目页不铺开待办清单，也不重复完整月度回顾。
- 沿用现有 `/api/projects` 身份与分类、状态、说明字段；结合 `/api/todos/projects` 提供人的投入与事项摘要，不新建第二套项目。独立多标签与阶段目标等待明确需求后再引入。

### 时间分配：精力实际去了哪里

- 按日期展示全部项目与未关联事项的真实投入，以事项为行、时间为横轴；保留独立的投入区间、修正入口与缩放。
- 工具栏仅展示日期导航，不继承「今天／全部待办」的项目筛选。

### 回望：我已经走过的路

- 以月为基本回顾单位，可切换月份。
- 统计仅展示有依据的数据：完成的不同事项数、记录的投入时长、有投入记录的天数。明确它们不是完整人生或全部工作时间。
- 「精力去向」按事项汇总，可切换按标签汇总。标签分配避免重复记时。
- 「这个月留下了什么」以时间线呈现完成的事情、成果链接、自己的短记；点开可回到完整历程。
- 「足迹」采用低压力纪念章：第一次完成、首次交付、持续推进同一想法等，从真实事件生成，能展开查看依据。
- 不设排名、生产力评分、连续打卡惩罚或「比昨天落后」提示。休息、暂停、尝试后放下都允许留下记录。
- AI 可基于已记录的事项和备注起草月度回顾，用户确认后保存；不编造情绪、意义或未记录的经历。第一版可以先不做 AI 回顾。

## 3. 精炼的数据与状态

### TodoItem：事项本身

`id / title / note / projectId? / state / plannedOn? / dueAt? / createdAt / firstStartedAt? / completedAt? / closedAt?`

- `state = idea | ready | doing | done | dropped`。
- 「今天」是按计划日期形成的视图，「归档」是结束后形成的历史视图，都不是额外状态。
- `firstStartedAt` 为首次真实投入的事实，`plannedOn` 为可修改的意图，两者不能混用。
- 初期每个事项至多关联一个既有项目，以保证时间汇总不重复；以后真有需求再添加其他标签。

### FocusSession：真实投入

`id / todoId / startedAt / endedAt? / source(timer|manual) / note?`

- 全局同时最多一个计时；切换事项会先结束上一段。
- 暂停结束一段，继续产生新的一段，不把中断时间算入投入。
- 支持事后补记、修改和删除，校验结束晚于开始、区间不重叠；跨午夜按用户时区分配到每天。
- 未结束记录单独标记，刷新或重启后恢复；长时间运行提示核对，不自行假定用户一直在工作。
- 不将 Agent 执行时长或终端后台运行时长当作人的投入。

### TodoEvent 与 DayNote：经历与回顾

- 事件只记录需要回溯的领域变化：产生、安排、首次开始、完成、放下、重新打开。不是完整事件溯源架构。
- 每日短记可独立于事项存在。纪念章与统计初期由事件和投入记录派生，不提前搭建游戏等级系统。

## 4. 和现有系统的边界

- 沿用顶层 `project` 的项目身份与资料；作为待办的可选关联，不创建第二套业务项目。
- 新建后端 `todo` 模块，拥有事项、投入、回顾与查询逻辑；提供 `/api/todos`、`/api/focus-sessions`、`/api/day-notes` 和 `/api/todo-reviews` 等明确入口。
- 现有 `ProjectProgressStore` 是会话续接材料，不复用为人的项目进度或时间记录。
- 现有 Agent `task` 是模型执行任务，不复用为个人事项。以后可显式关联，一个人的事项允许关联多次 Agent 执行。
- 结构化业务数据是事实来源。记忆可引用用户确认的事项事实，但不能反过来静默改变待办状态、补记工时。
- AI 接入后支持读取待办、提出拆分或排期建议，用户明确要求或确认后执行；第一版不需要复杂自动规划。
- 项目归档只影响标签可选性，不关闭所属事项；项目硬删除需先明确关联处置，不能顺带删除人的历史。

## 5. 第一版范围与验证

先实现事项增改、安排到某天、开始/暂停、完成/放下/重新打开、补记投入、项目筛选、每日回顾、月度汇总和历史时间线。延期：团队协作、依赖图、甘特图、复杂优先级、自动排期、等级商店。

关键验证：重复完成不重复计数；暂停不计时；全局单计时；跨午夜与时区；补记重叠；历史可追溯；项目标签生命周期不损害事项；休息日不触发负面反馈。

## 6. 布局预览的评估重点

今天主区是否足够聚焦；右侧投入记录是否适合常驻；「准备做」与「想法」是否符合日常直觉；回望的统计与具体经历是否平衡。

预览支持：三视图切换、项目筛选、录入想法、安排到今天、任务详情、开始/暂停、完成/重新打开、放下、补记时间、日记、月份切换。它采用固定演示日期 2026-10-16，数据只保留在当前预览会话；不是生产功能，也不是后台持久化实现。
