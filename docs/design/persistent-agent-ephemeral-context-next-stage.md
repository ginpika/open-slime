# Minis 动态上下文下一阶段需求

**Persistent Agent, Ephemeral Context · 个人单聊试点**

编写日期 2026-11-09

## 1. 目标与范围

用户可以在原会话里结束一段跑团、问一个代码问题，再回到跑团。三段对话都留在转录里。答代码时，Agent 不应收到上个任务的角色指令和未确认设定。回到跑团时，它应能恢复仍有效的角色约定，并按引用查阅旧过程。类似地，结束一次排障后，下一阶段应能找回根因证据和未决事项，同时避开反复尝试产生的旧日志。

本阶段沿用 `hub_session`、原消息 ID、Turn、任务和现有聊天入口。会话、转录、权限、任务、权威业务状态与原始证据由 Minis 保存。每次模型调用重新选择当前所需的材料。更换模型时，授权来源集合仍由 Minis 决定，实际入选内容可以随窗口和协议变化。

要分别解决四类问题。

| 问题 | 用户可见的失败 | 本阶段负责的机制 |
| --- | --- | --- |
| 历史长度 | 会话还远未填满窗口，旧过程却持续占用每次请求 | 当前工作窗口有独立上限，硬预算只负责最后的请求准入 |
| 内容构成 | 相似段落、重复日志和已失败的尝试盖过有效证据 | 限制默认过程回放，保留可发现的引用、不同版本和反证 |
| 权威性与时效 | 过期事实、已纠正的偏好、临时身份或撤回的结论重新影响答复 | 分开判定权限、适用范围、版本、有效期和指令权威 |
| 检索遗漏 | 证据退出请求后，Agent 找不到它，或把没有找到误当作不存在 | 可定位的证据索引、鉴权回读和可诊断的检索结果 |

本阶段在个人单聊落地，覆盖主回复、轮内补充输入、由单聊发起的子执行及其归纳、项目续接和现有待办审批试点。圆桌、心跳、Coding、具名 Agent 消息入口以及其他业务审批留在各自执行路径。当前阶段依赖现有模型协议和本地持久化。供应商原生压缩、后台自动重写长期记忆和模型自动切换任务均留待后续评估。

### 当前基线

[P1–P4 设计和试点](persistent-agent-ephemeral-context.md)已提供整份请求的估算预算、来源分页回读、出站 Manifest、P2 子执行隔离、P3 会话续接和 P4 专用待办审批。个人单聊的 `CONTEXT_EPHEMERAL_CHAT` 默认关闭，P2 随 P1，P3 和 P4 还分别需要 `CONTEXT_STAGE_CONTINUATION` 和 `CONTEXT_TODO_APPROVALS`。

[审查 A](persistent-agent-ephemeral-context-review-A.md)与[审查 B](persistent-agent-ephemeral-context-review-B.md)是问题记录。分支复制丢归属、改绑往返后旧委派恢复可见已经用当前 SQL 复现。现有六个 P1/P2 套件曾复跑 17/17，P3/P4 缺少专项用例。全量测试仍有记忆夹具失败，沙箱还会影响回环 HTTP 和临时文件操作。旧报告目录的 731 混有更早结果，后续基线使用单次 Maven 输出和独立报告目录。真实模型质量、成本和跨模型重组尚待对照。下文定义的是本阶段交付要求。

## 2. 会话、任务与请求的边界

| 概念 | 本阶段定义 |
| --- | --- |
| Conversation | 持久的用户入口与完整转录，沿用现有会话 ID。显示权限和模型读取权限分别判定 |
| Turn | 一次用户输入、轮内补充与对应执行。开始时捕获当前任务段和授权版本 |
| 任务段（Scene） | 会话内的一段工作，可覆盖多个 Turn。拥有临时角色、任务约束、局部历史与续接。普通聊天也有工作段，但界面无需展示每个普通段 |
| 续接 | 某个任务段仍需的确认项、约束、未决项与证据引用。正文和业务状态按现行权限重新读取 |
| Epoch | 某个工作段默认回放的历史水位及其变更记录。推进水位不会改动授权、任务段或原始材料 |
| 来源引用 | 可定位到原始记录的稳定标识，包含需要的内容版本或字符范围。分支本地 ID 可映射到原始来源 |
| 授权代号 | 由 Runtime 捕获和校验的单调版本。绑定改动、回退和撤回按各自规则使旧授权、旧执行或材料失效 |
| 审批回执 | 由待办服务提交的业务记录。历史中的助手话语和续接摘录只能引用它 |

### R1 · 在原会话内切换任务

- 个人单聊试点提供开始任务、结束回到普通聊天、恢复已有任务三个动作，并显示当前任务名。开始时可填写名称和可选的临时角色或任务约束，恢复时从本会话的可恢复任务中选择。切换只在安全点提交。生成中先让用户结束或取消当前轮。模型可以建议切换，话题分类和模型文字本身均不能改变活动任务。
- 每个 Turn 使用开始时捕获的任务段。结束任务时开启新的普通工作段，防止此前的普通段和刚结束的任务段一起被默认回放。保留稳定的 Agent 身份、已选提示词和适用规则。试点把跑团主持人之类的临时角色写入任务段，切换不会修改用户有意设置的全局 Agent 提示词。
- 恢复任务前校验会话、Agent、项目和来源。仍有效的任务约束与续接重新装配，退出任务期间的其他过程不会自动进入。用户显式确认带入的材料按类型处理，确认为新任务约束的内容以任务约束生效，旧结论和摘录作为资料。普通聊天和已结束任务的授权证据仍可经显式检索找回。
- 续接从每会话一份迁移为每任务段一份。只在来源和范围校验通过、Turn 成功结算后发布。已有会话续接在升级后不能默认变成新任务的约束。可核验的摘录仍可通过旧来源读取并明确带入，旧水位不沿用到新任务段。结束任务立即退出它的默认上下文，窗口水位独立处理。已发出的后台子执行可以结束并归档到发起任务段，只有仍获授权且与当前任务相关的结果才可自动入选。
- 有待审批的任务段可以离开。恢复原任务段并重新通过授权和版本校验后，用户才可批准该操作。回退、删除或改绑使旧审批失效。普通任务切换不会撤销原任务仍有效的证据。

**验收。** 在低于旧 85% 水位的同一会话依次执行“跑团 → 普通代码问答 → 恢复跑团”。逐次断言出站请求只含对应任务的角色和续接，代码问题保留 Agent 的稳定规则，恢复后的 Agent 能找回原约定。检查重启后的活动任务、生成中切换、轮内补充、晚到子报告和失效续接。任务切换、会话分支和模型切换分别测试。

## 3. 来源、撤回与历史兼容

### R2 · 复制转录时保留来源归属

- 新写入的用户消息、助手回复、轮内补充、工具记录、任务产物和可重新装配的派生材料，应能定位其来源类型与 ID、原始会话与 Turn/Task、Agent、项目和生成时作用域。可修改来源需要可比较的版本或内容校验值。授权时捕获的版本与原始归属分别保存，分支不能用目标会话绑定覆盖原始归属。
- 分支继续复制可见转录并分配本地消息 ID。对于创建时已获授权且可验证的来源，保留本地到原始来源的映射和需要的轮次配对。任务、执行、待办审批和阶段水位各有自己的生命周期，分支不继承其运行状态。原会话的回退、撤回或删除一旦使源记录失效，分支中的副本也退出模型可读范围。分支自身回退只影响该分支。原会话改绑后，依赖旧绑定授权的副本同样失效。
- 回退保留原会话仍获授权的普通消息前缀。它同时撤回被移除的来源，并作废旧在途执行和续接的授权。项目或 Agent 改绑开启新的绑定代号，即使随后改回原值，旧绑定产生的授权也不会恢复。没有项目的来源与归属无法判断的来源必须区分。
- 存量数据先尝试从现有 Turn、Task 和可信元数据补齐。只有能证明归属和用途的记录才沿用模型访问。无法证明的历史保持用户可见，从自动装配、模型回读和记忆提炼中排除。不能用当前绑定猜测原归属，也不能把未带依赖的历史摘要当成已验证结果。用户可以在当前任务主动提供自己可见的材料，按新输入处理。迁移应可重复执行，保留原 ID，并输出各类已确认和无法确认的计数。

**验收。** 覆盖同绑定的正常分支、连续分支、在用户消息处截断、缺配对的老数据、Agent 与项目各自的改绑往返、分支后撤回原始消息、分支自身回退。对同一条记录分别断言用户转录、自动装配、模型列表及逐条读取的预期结果。

### R3 · 让派生内容遵守来源的撤回

- Runtime 对每个用途分别做决定，包括自动装配、模型查找与回读、项目续接、子报告和批次归纳、待办提案以及记忆提炼。复用同一来源与权限判定，调用方再按当前任务决定是否相关。项目续接同时校验共享授权与每条摘录的原始来源。
- 对实际发送的可撤回材料记录持久依赖，包括入选的普通历史、召回、项目摘录、工具回读、续接和子报告。固定系统规则无需伪造证据引用。回复、子报告、批次归纳、续接及记忆提炼携带相应依赖。一个执行有多次模型调用时，合并可影响最终输出的依赖，包括被后续裁掉的中间证据。无法证明某段生成内容只用了其中一部分时，按整条派生内容处理。回复与依赖在同一结算中发布，避免出现正文已可回放、依赖尚未保存的间隙。
- 校验直接和间接依赖。任一必需来源被撤回、删除、更新到不兼容版本或退出授权后，派生内容退出后续模型请求、索引、回读和提炼。保持与该来源无关的材料可用。应用已有的转录显示与删除语义，已显示的历史和已提交的外部操作分别按各自规则处理。
- 装配后到发送前再次核验所选来源和当前执行授权。发送前授权检查以该次检查时已提交的版本为准，每次重新发送都要重验，不能以原样重传绕过。已提交到网络的请求无法撤回。发送后才发现撤回时，停止后续调用，取消仍在生成的回复，并阻止失效结果成为已完成答复、报告、回执或记忆。提交和事件投递前还要用当前版本复核。模型或网络调用放在事务之外。
- 将持久依赖和撤回记录与 Manifest 分开保存。Manifest 有留存限制，过期或重启后，鉴权和撤回仍需有效。查找结果和索引只展示当前可读来源的标识与元数据。失效引用的错误不泄露来源是否存在或曾属于哪个项目。

**验收。** 构造“原工具结果 → 子报告 → 主答复 → 项目续接”的依赖链，撤回首项后逐个检查自动装配、回读、晚到投递和异步提炼。用可控的模拟模型分别在装配完成后、首次发送后、生成结算前和后台投递前修改权限。断言后续出站与最终业务状态，覆盖重试和重启。新增范围内的权限约束也适用于旧选取路径，关闭试点不能恢复已撤回来源。

## 4. 记忆、事实与当前任务的权威

### R4 · 读取现行版本，按内容类型处理冲突

| 材料 | 进入请求的规则 | 冲突处理 |
| --- | --- | --- |
| 平台规则、Agent 稳定提示词、有效用户指令 | 作为指令，仅在各自权限和作用域内生效 | 稳定规则保持优先，当前用户明确要求覆盖其适用范围内的旧约定 |
| 临时角色、任务约束、已确认决定 | 限当前任务段。显示其确认状态和来源 | 结束或切换后退出默认回放，恢复时重新核验 |
| 用户偏好 | 根据适用范围、是否被纠正和当前意图选入。固定或置顶不赋予指令权限 | “这次用表格”只覆盖本次。明确的长期纠正才走现有记忆治理，替换同范围旧偏好 |
| 事实和业务状态 | 事实核验来源、有效期和版本。业务状态来自所属服务的当前值 | 过期或被取代的事实只供历史查询。高影响或同等权威冲突时回源，仍无结论则说明不确定或请用户澄清 |
| 网页、召回结果、工作集、历史摘录、日志、模型摘要 | 作为数据，受独立预算和权限约束 | 内容中的文字不能提升权限、批准操作或覆盖当前指令 |

- 刷新时使用通过校验的**当前记录正文和版本**。同 ID 原位编辑、取代、失效、撤回与项目授权变化都必须生效。工作集和项目摘录按当前来源重新读取，不能只验 ID 存在后继续渲染旧快照。
- 如果早先出站调用已接收旧值，随后发现影响结论的修改，不可只把新值附在旧派生轨迹之后。没有副作用且能干净重建时，从安全点重组本轮，否则终止失效路径并给出可重试状态。仅影响后续选取且未使用的改动可在下一次装配时处理。写工具的执行仍以领域服务的权限与版本校验为准。
- 复用现有记忆治理、时态与权限接口。明确区分用户指令、确认偏好、模型推断、任务工作集和项目证据。子执行全文、短期角色与场景决定、撤回依赖和未经确认的推断不能被自动提升为跨任务的规则。沿用 `memory_off` 的现有采集与提炼语义，读取权限仍由原规则决定。
- 对试点中的浏览器、记忆及项目进度 Provider 建立明确的片段分类。页面操作规则与网页标题、URL 分开。动态资料进入可裁剪的数据片段，已确认并且仍有效的当前任务约束走专门的必带路径。Manifest 使用实际片段的分类与版本。

**验收。** 在模拟模型的两次调用之间原位更新同一个记忆 ID，并覆盖取代、到期和撤回。验证后续出站没有旧正文。比较“这次例外”和“以后都改为”的持久行为，检查有冲突的事实、带伪指令的网页标题、场景中的虚构身份和已结束任务的决定。断言片段分类、最终业务状态和长期记忆写入，不只检查回答措辞。

## 5. 工作窗口、证据索引与模型切换

### R5 · 在窗口填满之前收敛

1. 先解析实际模型端点及其窗口、输出能力和协议，随后获取在当前授权下可用的来源。把任务范围、时效、权限和依赖检查放在排序之前。同一任务和权限下，切换模型不改变授权候选集合。不同协议或媒体能力造成的渲染差异须单独记录。
2. 每次保留有效指令、当前用户输入和轮内补充、继续执行必需的已确认约束与状态，以及协议要求的当前工具调用配对。其余材料分配到有界的局部工作和证据预算。试点初始值为当前工作段最多 8 个已完成 Turn，历史正文估算量另受可用输入预算的 25% 和 8,192 token 双重限制，取最紧的一项。当前输入和必需的当前工具交换单独计入总预算。旧数据无任务段时，同样使用有界窗口，直到首次显式切换。
3. 历史优先选取近期且相关的完整 Turn，并保留其时间顺序。相同优先级按时间与稳定 ID 排序，试点复用现有召回和元数据，选取本身不新增模型调用。重复或过时的过程材料可用简短说明与引用替代，保留有实质差异的版本、反证和未解决的失败。历史与工具交换的删减保持协议配对，保留原始工具记录。未产生业务结果的失败重试只保留对当前诊断有用的记录。
4. 在任务边界自动执行工作范围切换。现有 P3 高水位作为同一任务内的进一步整理手段，只有实际采用且成功结算的主请求才能提交 Epoch。低水位为目标，硬预算为准入约束。预算包含实际采用的工具定义、协议字段、媒体及输出与推理预留。若必带材料已超预算，返回明确原因并停止发送。
5. 同一个已解析模型配置决定端点和窗口。特别测试未配置 `env` 而回退到首个可用模型的情况。预算以估算和安全余量实现，单独记录供应商返回的实际用量。组装时保留稳定的片段标识与来源版本，协议转换或 JSON 拷贝不得丢失它们。

### R6 · 让退出默认回放的证据仍然好找

- 裁掉相关历史工具交换或旧过程时，在证据预算内给模型一个简短索引。首批最多 8 条，包含稳定引用、工具名或类型、时间或任务段，以及可用于定位的简短标签。索引只选当前获授权且相关的材料，不回放旧正文。已有原生工具记录直接引用 `message:<id>:tool:<索引>`，避免复制同一正文。
- 复用 `read_context_source` 的列出和读取接口，支持在授权范围内按关键词、任务段、类型或时间缩小范围。返回有界分页。读取按现有 Unicode 码点范围返回原文并标注版本。索引满额或未命中时，仍有路径主动查找已授权证据。已失效和从未存在的来源对模型返回同样的不可用结果。
- 能否列出、能否读回、是否进入模型请求以及是否支撑最终答案分别记录。需要证据但找不到时，Agent 应表达缺少依据或向用户索取材料。未经确认的摘要不能补成确定事实。

### R7 · 让出站结果可验证

`raw-context` 继续标记为预览，`context-manifests` 记录实际出站元数据。Manifest 至少可按会话、Turn、独立执行和调用尝试对照模型、工作段、授权代号、Epoch、实际使用的预算、已选来源版本与裁剪原因。诊断区分权限或版本失效、作用域不匹配、相关性排序落选、超预算裁剪、历史工具移出和检索未命中。记录本地出站与供应商计量的区别。普通诊断只保存元数据与受控引用，避免增加原始正文或凭据的留存。

**验收。** 固定数据库、权限、当前任务与工具，将同一个续接请求分别送给两个同窗口的模拟模型和一个较小窗口的模拟模型。比较授权候选引用、最终选取和协议配对。较小窗口可裁掉更多材料，已授权证据仍应可按引用读回。再跑一次端点回退用例，核对实际发往的模型、窗口、预览和 Manifest。对固定超长日志，先断言模型请求没有全文，再由索引定位并按范围读出指定根因及反证。

## 6. 子执行和待办的交付缺口

### R8 · 统一同步与后台子报告

同步限时内完成、超时转后台和直接后台执行，使用同一种持久结果和幂等投递。每个获授权的完成、部分完成或失败结果在用户转录中显示一张卡，正文存在时可展开全文。短结论和引用供主模型选择。批次成员确定后，只归纳该批获授权的终态结果，包括符合条件的同步结果。重试和重启按执行 ID 与批次去重。执行作用域与授权代号从父 Turn 捕获，任务段切换只改变默认装配，取消、撤回或改绑则阻止失效结果投递和回流。报告展示与全文回读不额外要求一次模型摘要调用。

**验收。** 覆盖立即完成、超时后完成、后台乱序到达、失败或部分结果、重启与重复投递。核对报告卡片、短结论、归纳成员、全文回读和长期记忆的独立结果。撤回来源后重放投递事件，旧结果不可复活。

### R9 · 让启用审批时的待办完成经过同一约束

- 在启用 P4 的单聊试点中，由模型完成待办必须经过审批。领域写入入口统一拦截未完成到完成的转换。直接新建已完成项、通过重排或删除再添加绕过现有项，同样不能跳过审批。现有已完成项可原样保留，普通的创建、排序和未完成状态调整继续支持。使用稳定待办 ID 和预期版本定位操作，序号只用于交互。关闭 P4 时沿用普通清单写入，已有待审批项仍按其授权处理。
- 提案、回复与原任务挂起一并持久化。决定前重新校验用户、任务段、授权代号、原轮次、待办版本和提案依赖。在同一短事务内提交待办变更、原任务终态、事件及回执。相同决定重试读回原回执，另一决定返回冲突。版本冲突在同一授权范围内显示失效。因回退、改绑或删除退出授权的审批从操作列表移除。
- 下一次相关任务的请求装配小型结构化状态，包括操作 ID、待办当前状态以及待确认、批准、拒绝或失效结果。旧等待话语可留在用户转录中，模型判断以当前状态为准。重启后可处理待审批操作，提交决定无需自动再启动一个模型执行。
- 本阶段为 P3/P4 组合采用显式延后。若本轮已暂存新续接或产生待提交的 Epoch，审批工具返回可识别的延后状态，不写提案且让本轮走正常结算。下轮可重新提出。若审批先进入挂起点，则本轮结束，不接受后续续接。用户应能看出哪一步已保存、哪一步尚未执行。

**验收。** 检查 `write_todos` 直接完成、整表替换、重排、删除后重建和审批并发修改。重启后批准、拒绝、同键重试与异决定冲突均检查数据库与下一次实际出站。验证离开后恢复任务段、回退、改绑、分支和两种 P3/P4 先后顺序。审批通过只产生一次业务变更，延后路径不丢续接。

## 8. 评测与上线门槛

### 8.1 先验证确定性行为

- 为 R1–R9 补集成用例。用 SQLite 验证迁移、并发和结算，用模拟模型或本地 HTTP 记录实际请求。断言来源可见性、版本、协议配对、已提交状态与回执。权限扩大、撤回材料回流、重复提交和无效工具配对任一出现即失败。
- 在 `backend` 下运行 `.\mvnw.cmd test`，类级回归用 `-Dtest` 指定套件。原有六套件为 `ChatEphemeralContextTest`、`ChatContextSourcesTest`、`ContextPlanTest`、`ChatContextManifestsTest`、`ScopedSubagentRunTest` 和 `SubagentDeliveryServiceTest`。另补 P3/P4、改绑、分支和撤回链路用例。
- 先修复记忆夹具缺 `temporal_json` 和向量用例缺 `memory_event` 等阻碍基线的设置，再用独立报告目录跑全量。若环境限制回环或临时文件操作，将该类测试单独列出，并在支持相应能力的测试环境复核。发布时附命令、配置和单次报告。
- 用试点开、关以及混合开关验证行为。迁移和撤回规则不能随选取策略开关失效。确认旧数据影响范围和仍可用的操作。

### 8.2 用配对试验分别测量四个因素

比较现有试点基线、只启用正确性修复、再启用任务段和工作窗口三组。证据索引另做开关对照。固定输入、模型及参数、工具、来源版本和评分规则。每个因素保留对照，具体覆盖如下。

| 因素 | 只改变什么 | 记录什么 |
| --- | --- | --- |
| 历史长度 | 增加不改变任务和权威的中性轮次。覆盖旧高水位以下及硬预算附近，配对控制关键证据位置 | 入选 Turn、上下文大小、当前任务完成率、已确认约束保留率 |
| 内容构成 | 在长度相当的版本中，将中性材料换成相似正文、重复日志或失败重试，保持根因和反证不变 | 重复过程占用、错误归因率、最新根因和反证是否被使用 |
| 权威与时效 | 保持正确事实可得，改变竞争材料的来源、版本、指令层或任务作用域。分别测事实、偏好、临时身份和决定 | 当前纠正采纳率、场景串入率、过期事实引用、冲突时是否回源或澄清 |
| 检索遗漏 | 对比证据已入选、已裁但可索引、获授权但索引未命中，以及已撤回或确实缺失 | 从候选、索引、发起读取、精确读取到最终使用的各环节成功率，以及缺证据时是否恰当表达不确定 |

首轮使用至少 16 个配对样例，每组因素至少 4 个。每个模型和配置对每个样例至少重复 3 次。覆盖“跑团 → 代码 → 恢复”和“长日志 → 复核 → 新任务”两个组合场景，使用至少两个实际支持的模型配置，包含窗口差异。真实模型评分结合程序化断言与人工可复核标准。固定候选与模拟模型只能验证系统行为，真实模型试验单独报告回答表现。

首轮试点对每个模型分别使用以下目标。纠正和可回读根因用例的通过率各至少 90%，任务串入比基线下降，普通短对话成功率回落不超过 5 个百分点。长日志与重复历史组的成功任务总 token 中位数目标下降至少 20%。这些是预设目标，执行前可依据冻结基线调整并记录理由。报告每组分子、分母、失败样例、实际用量和读取成本，避免将小样本当作普遍结论。成本统计包含主调用、子执行、归纳和证据回读，同时记录调用次数、缓存用量、首字延迟和 P95。供应商没有返回的指标标为缺失。

### 8.3 灰度、退出与交接

1. 先在测试数据库和明确选入的个人单聊运行。试点默认关闭。可用同一批候选材料比较两种选取结果，影子比较不额外召回、不调用模型、不产生业务写入。
2. 确定性用例通过后做真实模型对照。先上线持久化与鉴权修复，再灰度任务段、默认工作窗口和索引。选取策略可以单独回退，来源与撤回约束继续执行，已结束任务的指令也不能因回退策略而重新注入。P4 的启停按 R9 处理，保留有效审批的处理入口，授权失效的记录不可复活。
3. 交接时提交代码与迁移说明、需求到测试的对应表、旧数据兼容统计、代表性实际 Manifest 和脱敏评测结果。出现鉴权失败、撤回回流或重复业务提交时，停止扩大试点。若仅成本或模型质量目标未达成，记录是哪一个环节出了问题，继续保留选取策略灰度。
