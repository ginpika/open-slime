# 协作工作台

协作入口采用三级页面：起始页 → 项目页 → 任务会话页。系统外壳负责全局导航，页面内部不增加常驻导航侧栏，也不使用卡片包裹整个工作区。

## 概念与数据关系

- 项目承载长期工作方向和成员；复用现有 `project`，方向保存在 `note`。
- 任务承接围绕项目目标的一次推进，一项任务对应一个持续存在的多智能体主会话。返工和继续讨论留在原任务内。
- TODO 是任务内的具体执行项，继续复用原有任务板、负责人、依赖、状态与执行记录。旧 TODO 不会提升为项目级任务。
- 议题是任务内独立的局部沟通空间，拥有明确的父任务、参与成员和独立消息记录。它可以澄清问题、解决分歧、形成决定，不等同于执行子任务。
- `collaboration_issue` 只保存主会话与议题会话的关系、卡片对应消息及结论；讨论内容继续使用现有消息与运行时。议题不再嵌套。
- 项目成员保存在 `collaboration_project_member`。首次使用时从已有主任务成员推导，空项目默认使用现有名册；调整成员只改变后续新任务的默认选择，既有任务参与人保持不变。

## 页面

### 起始页

列出全部项目，支持搜索、新建项目。采用连续项目行，延续编程起始页的方向。未归属项目的历史协作单独列出，允许打开后整理到项目。

### 项目页

展示工作方向、成员和推进任务列表。方向和成员按需编辑；从这里建立新任务并进入会话。议题会话不混入任务列表。

### 任务会话页

桌面采用双栏：左侧为主视图，Tab 只有“消息”和“协作图”；右侧为主任务的 TODO。输入框属于消息视图，协作图使用完整可用空间。

消息使用连续正文阅读，保留虚拟列表、思考链和原始上下文入口。议题以特殊卡片出现在发起时的位置；卡片呈现问题、参与成员、状态和简短结论。协作图同时提供真实协作事件与议题的入口。

进入议题后，主视图显示清楚的议题标题、返回主会话入口和输入范围；右侧 TODO 仍属于主任务。主会话与各议题分别保留草稿和阅读位置。

提交议题结论后，完整结论留存在议题内，并作为系统通知写回主任务；主流卡片展示简短结论，完整内容可继续查看。已提交结论的议题只读。执行受阻先回报主控，按需建立局部议题；关联待办的结论补入说明，由主控决定是否重新派工。关闭议题本身不代表待办已验收。

窄屏通过 TODO 按钮打开副视图，Escape 可收起；保持 16px 核心阅读正文，使用主题颜色和 AppIcon。

## 运行边界

### 项目工作目录

项目页提供“设置工作目录”，会话页工具栏也可进入。用户明确选择工作空间中的现有目录，或在选定位置新建独立目录。目录校验、规范化根路径与工作空间身份复用 `WorkspaceProjects`，`project_workspace` 保存协作项目与已验证编程项目的对应关系；不按名称、最近使用或名册顺序推断路径。

未绑定的协作项目仍可讨论与规划，不能通过终端或 `coding_task` 自行挑选现有代码项目。绑定后，主任务、局部议题、执行者和检查者得到同一目录上下文；`coding_task` 的列表、创建和运行访问仅限绑定仓库。终端目标还须满足成员已有工作空间权限，每次命令从绑定的规范化根目录启动，绑定失效或目录不存在时拒绝，不回退。

项目仍在讨论或执行时不能调整目录。绑定后会通知各会话重新核对既有成果，最近的目录变更通知固定进入上下文；原对话、成果及文件不会自动删除或撤销。此处固定终端的执行起点并限制目标，不将任意 shell 命令声明为文件系统沙箱。独立单人成员会话未关联协作项目时保留原有行为。

- 发言、停止、流式输出继续复用 `roundtableLive` 和现有后端运行时，切 Tab 或离开任务不会终止发言。
- 新任务有明确名称、项目关联、至少两位显式参与人和一位主控，创建时保留项目方向快照。会话页展示主控、阶段、验收标准与调度依据。
- 议题参与人必须属于父任务；创建与关联在同一事务中完成，并提供发起时的有界上下文快照。
- 议题仍在讨论或执行时不能提交结论；重复提交结论不会向主任务重复投递。
- 有议题关联的任务不能单独调整项目归属；删除通过任务生命周期入口统一清理主会话及议题，避免孤立记录。
- 主控明确请求相关成员讨论时建立独立议题；执行者的受阻先回报主控，议题内通过 `resolve_issue` 回传结论供主控决定。请求用户则暂停当前会话。具体推进规则见 [协作运行机制](collaboration-autonomy.md)。
- 既有历史保持原样，不根据文字推断或补造议题。

## 路由与验证

`#/collaboration` 为项目起始页；`?project=...` 为项目页；`?project=...&task=...` 为任务会话；增加 `&issue=...` 进入议题。地址支持刷新和浏览器前进后退，父任务、项目与议题归属不匹配时不提供发送入口。

旧 `/roundtable` 与 `/workflow` 入口继续可用，分别进入最近任务的消息和协作图。

验证命令：

- `npm --prefix frontend run build`
- `npm --prefix frontend run test:collaboration`
- `npm --prefix frontend run test:collaboration:browser`
- 后端 `CollaborationServiceTest`、`Roundtable*Test`、`ProjectWorkflowTest`、`LayeringTest`

浏览器使用隔离测试数据，覆盖三级导航、项目方向和成员、任务创建失败恢复、议题消息与草稿隔离、结论回流、发送时切图、真实待办操作、57 项历史拖拽、旧入口和四种主题的桌面及窄屏。

## 任务归档与删除

项目页任务行与“任务设置与成员”均提供归档、恢复和删除。归档的任务默认从推进列表收起，可在“已归档任务”中查看或恢复。归档保留全部记录，主会话和议题停止接收发言、回退与待办干预；恢复只恢复可见与可编辑状态，等待新的用户发言后继续执行。

主任务、关联议题或委派编码任务仍在讨论、排队、执行时，服务端拒绝生命周期操作，前端显示原因。删除需要前端确认；服务端在同一事务内清理主会话及全部所属议题、消息、话题事件、TODO、协作执行记录和续接授权，撤回这些来源的派生记忆并清除检查点。独立编码任务保留在编程工作台，解除已删除会话的关联；已经修改的项目文件不会被删除或回滚。

生命周期接口为 PUT /api/agents/collaboration/tasks/{id}/archive（archived=true/false）与 DELETE /api/agents/collaboration/tasks/{id}，沿用 SSO 身份绑定。局部议题不能通过该入口独立删除或归档。

CollaborationTaskLifecycleTest 使用真实 SQLite 验证关联清理、归档只读、显式恢复、运行拦截与失败回滚；浏览器夹具覆盖列表和设置入口、确认取消、失败保留、刷新后的归档状态及 320/390 窄屏。
