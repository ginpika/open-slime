# 执行态协作视图

执行态围绕一场圆桌回答：谁在推进、任务为什么等待、刚发生了什么、是否需要用户参与。智能体页承担全局名册和忙闲概览。

## 观察范围

- 默认选择最近更新的圆桌；使用窗口内状态保存选择，切页返回后继续查看同一场圆桌。
- 协作和任务两个视角使用同一 `sessionId`，切换视角不改变数据范围，也不重新请求另一套状态。
- 会话选择器提供次级入口「全局活动总览」，继续复用已有全局接口。
- 「前往圆桌」同步圆桌页的窗口内会话选择，不打断后台执行。

## 图的含义

- 协作视角：成员围绕话题排列，成员与任务的箭头表示负责关系。
- 任务视角：依据 `dependsOn` 排列层级并绘制有向依赖边。相邻任务不自动相连，独立任务允许并行。
- 定向交流只从持久化事件的目标字段恢复。选中历史讨论请求后显示虚线，并明确标注为历史关系。
- 不从公开发言顺序推断私下交流，也不推断消息已经接收或已经处理。
- 同一观察范围和视角内，刷新状态不重置缩放和平移；选择历史事件不移动已有节点。

## 状态和记录

智能体页及执行态共用头像状态标记和岗位标签。蓝点表示工作中、绿点表示空闲；初次读取或更新失败使用灰点及明确文案。圆桌发言者也计入工作状态。

`WorkflowView.events` 合并当前会话的公开消息摘要和运行时协作信号，最多返回 30 项。公开消息只读取摘要字段，不读取思考、工具过程或请求上下文；任务详情仍使用既有执行记录接口。时间线不参与调度，也不成为另一份状态正本。

首次加载与空态分开呈现。后台刷新失败时保留同一会话的上次快照并提示更新时间；切换会话时不会把上一场圆桌的数据展示为新会话状态。轮询在前次请求结束后再安排，避免重叠和响应倒序。

## 验证

- `npm --prefix frontend run build`
- `npm --prefix frontend run test:workflow:browser`：使用本机构建和隔离 API 样本，覆盖加载、真实依赖、历史定向关系、任务操作失败、跨页选择、动态忙闲和四主题桌面/窄屏布局。
- `RoundtableActivityTest`：有界摘要、会话隔离、信号目标、旧载荷兼容及合并排序。
- `RoundtableWorkflowActivityTest`：全局/会话执行活动及公开发言的忙闲统计。

浏览器检查可以通过 `MINIS_PLAYWRIGHT_DIR` 指向已安装 Playwright 的 `node_modules` 目录。后端使用 Mockito 的环境如果不支持动态挂载，可以通过测试 JVM 的 `-javaagent` 参数加载相应版本的 Mockito jar；无需更改生产配置。
